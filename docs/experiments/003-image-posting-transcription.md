# 실험 003 — 이미지로만 된 공고를 모델이 옮겨 적을 수 있는가 (전사 B 방식)

조사 단계(`docs/design-research-stage.md`)는 이미지·스캔본 PDF를 모델이 읽어 텍스트로 옮기는 전사(B)를 쓴다.
대기업 공채 공고는 본문이 "지원하러 가기" 몇 글자뿐이고 내용이 스크린샷 이미지 1장인 경우가 흔해서(크롤러 레코드 13건 중 현대오토에버·지원처 7·지원처 13·지원처 12·지원처 9 등 대기업 공고가 전부 이 모양, `images` 1개·본문 7자),
전사가 안 되면 분석 단계(요구 뽑기)부터 비어 버린다. 이 문서는 첫 실측과, 그 결과로 바꾼 것을 기록한다.
**결과가 나올 때마다 이어서 적는다.**

vault 상태: 해당 없음(vault를 검색하지 않았다).

## 1. 첫 측정 (2026-10-10)

### 조건
- 입력: 현대오토에버 "2026 4분기 신입사원 채용"(inthiswork 402384)의 공고 이미지 1장. 1191×8000px, 내용은 PNG(CDN이 `.webp` 주소로 PNG를 내려줌), 430KB.
- 모델: `us.anthropic.claude-sonnet-4-6`(`MAS_MODEL_ID` 미설정, 기본값). temperature 0.
- 방식 ①: 이미지 한 장을 한 번에 전사(조각내기 없음). Bedrock 호출 1회, 28.7초, 3830자.
- 방식 ②: 빈 줄에서 1400px 안팎으로 잘라 조각마다 전사(`split_tall_image`). 조각 6개, 호출 6회, 45.7초, 4068자.
- 정답 기준: 같은 이미지를 **원래 해상도 조각**(세로 300~900, 2400~3500, 3480~4380, 4380~5300)으로 잘라 눈으로 읽은 내용. 읽은 쪽은 이 세션의 모델(Claude)이고 사용자의 확인은 아직 없다.

### 확인된 것
- **세로로 긴 이미지를 한 번에 전사하면 작은 글씨 구간에서 그럴듯한 다른 단어로 바뀌고, 없는 내용을 지어내기도 한다.** 이 이미지에서는 대조한 구간 거의 전부에서 오류가 났다.
- 같은 이미지를 빈 줄에서 1400px 안팎으로 잘라 전사하면, 대조한 범위에서는 오류가 없었다. 원래 해상도 조각에서는 글씨가 또렷이 읽혔다.
- 조사 단계의 인용 대조(`quote`가 자료에 있는지)는 **이 오류를 잡지 못한다.** 잘못 옮겨진 글이 "자료"가 되기 때문이다. 오류를 줄일 곳은 전사 단계다.
- 확장자와 내용이 다른 이미지가 실제로 있다(`.webp` 이름의 PNG). 형식을 확장자로 정하면 Bedrock에 틀린 형식을 알리게 되므로 파일 첫 바이트로 정하도록 고쳤다(`detect_image_format`).
- 이 공고에는 자격요건·우대사항 같은 "요구 목록"이 거의 없다. 지원 요건 3줄(전공 제한 없음, 학사/석사 또는 2027년 2월 졸업예정자, 해외여행 결격사유 없음)과 직군별 직무 이름 목록이 전부다.

### 확인되지 않은 것
- **이미지 전체를 대조하지 않았다.** 위 표 밖(온라인 채용설명회 표, 문의 방법, FAQ 본문, 기타사항 문구)은 원본과 한 글자씩 맞춰 보지 않았다. 조각 전사가 "대조한 범위에서 오류 없음"이지 "전부 정확"이라는 뜻이 아니다.
- 대조도 모델이 했다. 사용자가 원본과 직접 맞춰 본 것이 아니다.
- 조각 높이 1400px은 근거 없는 시작값이다. 더 크거나 작은 값에서 어떤지는 시험하지 않았다. 한 번에 보이는 한계가 정확히 몇 px인지, 모델이 이미지를 내부에서 얼마나 줄이는지도 확인하지 못했다(오류가 난 것은 실측이지만 원인이 축소라는 것은 추정이다).
- 표본이 이미지 1장·모델 1개다. 다른 공고 이미지(사진이 섞인 것, 가로로 넓은 것), 스캔본 PDF는 시험하지 않았다. 사진처럼 빈 줄이 없는 이미지는 아무 곳에서나 잘리므로 경계의 글이 틀릴 수 있다(단위 테스트로 동작은 확인, 품질은 미확인).
- 같은 입력을 반복했을 때 결과가 같은지(재현성)는 보지 않았다.

### 바꾼 것
- `tools/sources.py`: 세로로 긴 이미지는 빈 줄에서 조각내 조각마다 전사하고 순서대로 잇는다. 한 조각이라도 실패하면 일부만 쓰지 않고 못 읽음으로 둔다. 이미지 처리에 Pillow가 필요해 `sources` extra에 더했고, 없으면 이미지는 한 번에 읽지 않고 못 읽음으로 처리한다(틀린 글을 만드는 것보다 낫다고 판단).
- 이미지 형식은 확장자가 아니라 파일 내용으로 정한다.
- 전사 프롬프트에 "그럴듯한 다른 단어로 바꾸지 않는다"와 "입력이 큰 문서의 일부일 수 있다"를 더했다. 이 문구가 오류를 줄이는지는 따로 재지 않았다(조각내기와 함께 바뀌어 효과를 가를 수 없다).
- `scripts/transcribe_file.py`: 이미지·PDF를 텍스트 파일로 옮긴다. 이미지로만 된 공고를 공고 본문 텍스트로 만들 때 쓴다.

### 다음
- 사용자가 `inputs/postings/hyundai_autoever_2026q4.txt`를 원본 이미지와 맞춰 보고 고친다(전사본이라는 점은 변하지 않는다).
- 같은 방식을 다른 대기업 공고 이미지에도 돌려 오류가 비슷한지 본다.

## 2. 조사(Researcher) 첫 실행 (2026-10-10)

위 1절의 조각 전사본(`inputs/postings/hyundai_autoever_2026q4.txt`)을 공고로, 웹 URL 7개를 자료로 `scripts/research_brief.py run`을 돌렸다. Bedrock 호출은 조사 1회(전사 호출 없음). URL은 사용자가 고르지 않고 이 세션의 모델이 웹 검색 결과에서 골랐다(공식 사이트 2, 2026년 실적·동향 기사 4, 채용 페이지 1. 2021년 기사는 오래돼서 뺐다).

### 결과
- 자료 8건(공고 1 + 웹 7) **전부 "읽음"**. 못 읽음 0건. 자료당 1039~4818자.
- 주장 21개(사업·주력 제품 6, 최근 동향 7, 산업 이슈 3, 조직·문화 3, 채용 직무의 맥락 2). 인용이 자료와 맞지 않아 코드가 **버린 주장 7개**. 못 다룬 주제 3개(복리후생·사내 제도, 경쟁사·시장 점유율, 직무별 업무 내용).
- 주장마다 원문 인용과 출처가 붙었고, 수치(매출 2조1864억원, 영업이익 1117억원 등)는 기사 문장과 일치한다.

### 확인된 것
- 공식 사이트와 뉴스 페이지는 우리 가져오기 도구로 본문이 읽힌다(표본 6개 페이지). 뉴스 페이지는 앞에 메뉴·구독 안내 글이 섞여 오지만 조사 결과에는 본문 주장만 남았다.
- 의심 가는 주장 3개(c6 엔터프라이즈 IT 제품 목록, c10 성장 배경, c13 대표 취임 후 첫 분기)를 자료 원문에서 찾아봤고 모두 같은 자료에 근거가 있었다. 지어낸 내용은 못 찾았다.
- 그러나 **보고서에 보이는 인용이 주장의 일부만 뒷받침**한다(c6의 인용은 H Chat 문장뿐, 나머지 제품은 다른 문장). 사용자가 인용만 보고 확인하면 근거를 못 찾을 수 있다.

### 확인되지 않은 것·문제로 드러난 것
- **채용 페이지(`career.hyundai-autoever.com`)는 막히지 않고 메뉴 글자 1039자만 읽혔다**(Teams / People / FAQ / 로그인…). "본문이 200자보다 짧으면 못 읽음" 기준을 메뉴 글자가 넘어서 "읽음"이 됐다. 이 기준은 메뉴만 있는 페이지를 못 거른다. 이 페이지에서 나온 주장은 슬로건 한 줄(c17)뿐이다. 조사 보고서의 "못 읽은 자료"가 실제보다 적게 나온다.
- 버린 주장 7개가 무엇이었는지 **기록에 남지 않았다**(내용 없이 개수만). 점검할 수 없어서 버린 주장의 내용을 경고에 남기도록 고쳤다(`MAX_LISTED_DROPPED`).
- 보고서를 한 글자씩 사실 대조한 것이 아니다. 위 3개 외 주장은 인용 문장이 자료에 있다는 코드 대조까지만 거쳤고, 주장이 인용을 넘어선 곳이 더 있는지 전수 확인하지 않았다.
- 사용자가 보고서를 읽고 승인하기 전이다(`approve` 전).
- 표본이 회사 1곳·URL 7개다. 로그인 벽·봇 차단이 실제로 걸린 페이지는 아직 만나지 못했다(상태 코드로 막히는 경우의 처리는 단위 테스트로만 확인).
- 이 보고서가 초안을 나아지게 하는지는 작성 단계를 돌려 봐야 안다(문항과 지원 직군이 필요).

## 3. 검색으로 URL 찾기 첫 실행과 직접 고른 URL과의 비교 (2026-10-10)

같은 공고(현대오토에버)를 URL을 주지 않고 `research_brief.py run`의 검색만으로 조사했다(Tavily 키 등록 뒤. 검색 질의 4개 → 후보 10개 + 중복 제외, 읽은 자료 11건, Bedrock 조사 1회). 2절의 보고서는 이 세션의 모델이 URL을 골랐다. 검색은 호출마다 후보가 조금 달라질 수 있어서(두 번 호출에서 4번째 질의의 상위 결과가 달랐다) 재현성은 보지 않았다.

| | 직접 고른 URL (2절) | 검색으로 찾은 URL |
|---|---|---|
| 읽은 자료 | 8건(공고 1 + 공식 2 + 기사 4 + 채용 페이지 1) | 11건(공고 1 + 공식 1 + 나무위키 2 + 위키백과 1 + 기사 3 + 잡코리아 1 + 사람인 1 + 시장 보고서 1) |
| 주장 / 버린 주장 | 21 / 7 | 20 / 10 |
| 실적 수치 | 2026 상반기 매출·영업이익, 사업부별 증감, 해외 비중, 계열사 매출 비중 등 구체 수치 | 2026 2분기 실적·증권가 전망·주주 구성. 반기 실적 기사는 못 찾음 |
| 공식 사이트에서 살아남은 주장 | 6개(회사소개·mobilgene) | 0개(10개 자료 중 공식 사이트 자료는 전부 인용 불일치로 버려짐) |

### 확인된 것
- Tavily 호출이 되고(키 파일 권한 600), 질의 4개 모두 결과가 왔으며 오류 없이 보고서까지 이어졌다. 검색으로 찾은 자료에는 보고서에 `검색: <질의>` 표시가 붙는다.
- 검색은 엉뚱한 자료도 가져온다. "산업 동향 시장 전망" 질의가 **자동차 선루프 시장 보고서**를 가져왔다. 조사 단계의 모델은 그 자료를 쓰지 않았고 "회사와 직접 관련이 없어 활용하지 않음"이라고 못 다룬 주제에 적었다(관련성 판단은 읽는 단계가 하는 설계가 이번에는 통했다. 한 번의 관찰이다).
- 검색 결과에는 2014년 채용설명회 자료(잡코리아)처럼 **오래된 자료**가 섞여 주장 3개가 나왔다. 보고서에 "2014년 채용설명회 기준"이라고 적혀 있어 사용자가 거를 수는 있다. 나무위키·위키백과(누구나 고칠 수 있는 자료)에서도 주장 7개가 나왔다.
- 검색 결과는 공식 사이트 소개 페이지를 찾았지만 직접 고른 쪽의 반기 실적 기사(구체 수치)는 찾지 못했고, 대신 계열사 매출 의존·외부 존재감 미약 같은 **비판적인 기사 논조**의 주장이 산업 이슈에 들어왔다. 지원동기 글에 쓸 자료로 어느 쪽이 나은지는 사람이 판단할 일이다.
- 버린 주장 10개의 내용(함께HAE 노조, SI·ITO·차량 SW 합계 매출, Refresh 휴가, 성비 등)은 검색해 온 자료 안에 **실제로 있었다**(원문에서 문구를 찾았다). 모델이 원문을 그대로 옮기지 않고 바꿔서 인용해 코드가 버린 경우가 섞여 있다는 뜻이다. 맞는 주장을 잃는 쪽의 실패라 안전한 방향이지만 정보 손실이다. 직접 고른 URL 쪽 버린 7개는 내용을 기록하지 않아 같은 점검을 못 했다.
- 위 점검 때문에 버린 주장 옆에 **인용 문장도 남기도록** 고쳤다(`QUOTE_PREVIEW_CHARS`).

### 확인되지 않은 것
- 어느 방식이 더 나은 초안을 만드는지(보고서가 초안을 나아지게 하는지)는 작성 단계를 돌리지 않아서 모른다.
- 인용 불일치가 왜 생기는지(문장 합치기, 따옴표·공백 차이, 요약 등)는 인용을 남기기 전 실행이라 모른다. 이번 실행의 인용은 기록이 없다. 허용 범위를 넓힐지(공백·따옴표 무시 등)는 인용을 보고 정한다.
- 표본이 회사 1곳·실행 1회씩이다. 검색 질의 틀은 처음 정한 것이라 "산업 이슈" 질의가 어긋난 것이 질의 때문인지 검색 서비스 때문인지 가르지 못했다.
- AWS Web Search Tool(설계 문서 18.1절)과는 비교하지 않았다.

## 4. 인용 불일치 원인 분석과 대조 규칙 보정 (2026-10-10)

3절에서 버려진 주장의 원인을 보려고 `research_brief.py reresearch`(저장해 둔 자료 11건으로 조사 모델만 다시 실행, 웹 접근 없음, Bedrock 1회)를 새로 만들어 같은 자료로 다시 돌렸다. 이번에는 버린 주장 옆에 인용을 남겼다. 모델 답은 매번 같지 않아서 3절의 10개와 정확히 같은 주장은 아니다(9개가 버려짐).

### 원인 (버린 9개의 인용을 자료 원문과 글자 단위로 대조)
| 원인 | 건수 | 내용 |
|---|---|---|
| A. 생략 표시(…)로 여러 조각을 이은 인용 | 4 | 첫 조각은 원문에 그대로 있음(나머지 조각은 인용이 100자에서 잘려 보여 이 대조에서는 확인하지 못함) |
| B. 따옴표 모양 | 1 | 원문 ‘모빌진’(곡선)을 모델이 '모빌진'(직선)으로 적음 |
| C. 위키 각주 번호 | 1 | 원문 `류석문 전무[4]의`에서 `[4]`를 빼고 인용 |
| D. 목록·표 기호 바꿔 쓰기 | 3 | 원문 `-`를 `/`로, `**코딩테스트**`를 `→ 코딩테스트`로 바꿈(공고 전사본 쪽) |

### 보정 (`engines/strands/researcher.py`)
- 따옴표 모양을 통일하고, `[숫자]` 각주 표시와 `**` 강조 표시는 비교에서 무시한다. 글자의 의미를 바꾸는 보정은 아니다.
- `…`로 이은 인용은 **조각마다 4글자 이상이고 원문에 순서대로 있을 때만** 인정한다(`MIN_FRAGMENT_CHARS = 4`, 근거 없는 임의의 시작값). 조각이 이어진 문맥인지는 보지 않는다(조각이 각각 원문에 있다는 것까지만 본다).
- 목록 기호를 다른 기호로 바꾼 인용(D)은 보정하지 않는다. 글자가 달라진 것이기 때문이다. 대신 프롬프트에 "인용 안의 기호를 바꾸지 말고, 건너뛸 때는 …를 쓰며 조각은 4글자 이상"을 더했다.

### 결과 (같은 자료 11건, 같은 코드 조건에서 비교)
| | 보정 전(3절 재실행) | 보정 후 |
|---|---|---|
| 주장 | 21개 | 27개 |
| 버린 주장 | 9개 | 2개 |

남은 2개는 `SI … ITO … 합계`, `류석문 … 전무 직급`처럼 4글자 미만 조각이 있어 규칙이 의도대로 거절한 것이다.

### 확인된 것
- 새로 통과한 주장 중 `…` 인용이 든 6개를 읽어 봤다. 조각들은 원문에 순서대로 있고(코드와 같은 정규화로 위치 확인), 주장 내용도 인용과 맞았다. 단 c14("외부 시장 비중이 제한적이라는 평가")는 인용이 경쟁사 이야기이고 "현대오토에버가 제한적"이라는 부분은 같은 기사의 다른 부분에서 온 것이라 **인용이 주장의 일부만 뒷받침**한다(2절과 같은 문제).
- 이 점검에서 제 확인 스크립트가 조각 2개를 못 찾았다(위치 -1). 원문에 각주 번호와 `**`가 끼어 있어서였고, 코드와 같은 정규화로는 찾았다. 확인용 스크립트도 같은 정규화를 써야 한다.

### 확인되지 않은 것
- 새로 통과한 21→27의 6개를 전부 사실 대조한 것은 아니다(`…` 인용 6개만 읽었다). 규칙을 느슨하게 해서 틀린 주장이 통과하는 비율이 늘었는지는 보지 못했다.
- 보정 후 결과는 한 번의 실행이다. 모델 답이 매번 달라서 같은 효과가 반복되는지는 모른다.
- 표본이 회사 1곳이다. 다른 사이트(각주가 다른 모양인 위키, 다른 마크다운 등)에서의 보정 범위는 모른다.
- 보고서에 보이는 인용은 정규화된 모양이라(곡선 따옴표→직선, 각주 번호 제거) 원문 페이지에서 글자 그대로 검색하면 안 걸릴 수 있다.

## 5. 직무를 정한 뒤 직무 맞춤 조사 (2026-10-10)

사용자가 지원 직군을 정했다(코딩테스트 전형 / 엔터프라이즈IT — Backend Developer, AutoEver Code 기능 개발·운영). 공고 이미지에는 직무 이름 목록뿐이고 직무 상세(JD)는 지원 페이지에 있어서, 사용자가 그 내용을 정리해 주었다. 그 정보를 공고 텍스트 뒤에 "지원 직군 상세(사용자 제공, 원문 아님)" 섹션으로 붙인 새 공고 파일로 조사를 다시 돌렸다(검색 질의 기본 4개 + 직무 맞춤 2개, 후보 14개, Bedrock 1회).

### 결과
- 주장 23개, 버린 주장 0개(경고 없음), 못 읽은 자료 3건.
- **막힌 사이트가 처음으로 "못 읽음 + 이유"로 남았다.** investing.com 기사 2건은 HTTP 403(차단), `hyundai-autoever.com` 첫 화면은 본문 6자(JS로 그려지는 페이지로 보임). 보고서에 이유와 "저장·캡처해서 입력 폴더에 넣어 달라"는 안내가 나온다.

### 확인된 것
